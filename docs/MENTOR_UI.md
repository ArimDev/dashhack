# Mentor Teams workspace

The Teams notes button opens a right-side modal drawer on desktop and a full-screen dialog below 1024px. The grid stays in place. Issues and mentor notes use separate columns; completed tracked notes appear in a quieter Done section underneath. A fixed close control and desktop full-height fold rail remain visible during scrolling. Opening/closing uses short native browser animations, disabled for reduced motion. Focus is contained in the dialog and returns to the original trigger.

Editors remain mounted when the drawer closes so failed or unsaved drafts are retained. Acknowledged saves move cards between sections; failed saves retain the editor and provide an explicit retry. Focus follows a converted card after saving. In Teams, **Change to issue** changes both type to help_request and tracking to true. Changing back sets mentor_note and tracking false. Both directions require an inline confirmation; Cancel or Escape dismisses that prompt without saving the conversion. Content, creator, assignee, status and priority are retained. Kanban's independent tracking/type controls remain unchanged. Existing server ownership/revision checks and automatic history apply.

Team descriptions and project abstracts are fully visible in separate rows above Originalita. Below 1024px, numbered teams follow numeric order instead of desktop seating-column order. Stable IDs preserve mounted editors through filtering and viewport changes. Search, page title and team picker share one compact header row. The menu adapts automatically: labels at 1280px+, icons at 1024–1279px, mobile menu and bottom navigation below that.

The Teams palette retains Bluey, with restrained borders/corners, warm issue/priority accents and distinct Critical labels. The fold rail uses pale Bluey in light mode and muted navy in dark mode. Arrow contrast is approximately 7:1 / 8.7:1. The drawer dims and lightly blurs the background. The Teams page scrollbar follows the same palette. These new visual rules are scoped to mentor Teams and its drawer; public wall and moderation presentation are unchanged.

Teams refreshes every 15 seconds while visible, plus on focus/visibility return. Reads do not replace active fields, dirty notes, pending saves or newer revisions. No schema, dependency, provider settings, background service or production data migration is involved.

Validation: 145 unit tests / 1136 assertions, pinned Bun 1.3.2 production build with native image packaging, and 28 Chromium scenarios against the isolated production HTTPS runtime pass. Coverage includes both confirmed conversions with real persistence, Cancel making no write, delayed acknowledgements, failed-draft recovery, focus restoration, numeric mobile ordering, responsive navigation, full abstracts, guests, assignment, Kanban, matrix/History/metrics and wall regressions. Phone checks are browser emulation. Persistent browser coverage lives in mentor-sidebar.spec.ts; compact-note/mobile tests use the new drawer context. Production preservation checks are recorded in RAILWAY.md.
